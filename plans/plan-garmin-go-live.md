# Plan: switching on Garmin sync

The app follows Garmin's published OAuth 2.0 PKCE specification for connecting accounts. The one part not yet
checked is the exact format of Garmin's activity notifications, which Garmin documents for approved developers.

## 1. Verify the notification format (before anyone connects)

- [ ] Get the Activity API documentation from the Garmin Developer Portal (notification section: push and ping
      formats for activity summaries, activity details and activity files; deregistration; user permission change)
- [ ] Compare field names with what the app reads in `xcapp/garmin.py`:
  - `handle_notification` / `_handle_item`: top-level keys `activityFiles`, `activities`, `activityDetails`,
    `deregistrations`, `userPermissionsChange`; per item `userId`, `callbackURL`, `fileType`, `activityType`
  - `summary_to_parsed`: `summaryId`, `activityId`, `activityType`, `startTimeInSeconds`, `durationInSeconds`,
    `distanceInMeters`, `averageHeartRateInBeatsPerMinute`, `maxHeartRateInBeatsPerMinute`, `deviceName`
  - `details_to_parsed`: `summary`, `samples` (`startTimeInSeconds`, `heartRate`, `totalDistanceInMeters`), `laps`
- [ ] Fix any differences in those three functions only, and update the payloads in `tests/test_garmin.py` to
      match Garmin's examples; run `pytest -q`
- [ ] Confirm the file download host (default `apis.garmin.com`, setting `GARMIN_FILE_HOSTS`)

## 2. Configure

- [ ] App hosted at its https address (`BASE_URL`), with `SECRET_KEY`, `TOKEN_KEY` and `GARMIN_WEBHOOK_SECRET`
      generated by `python -m xcapp.cli gen-keys` (never change `TOKEN_KEY` afterwards)
- [ ] `GARMIN_CLIENT_ID` and `GARMIN_CLIENT_SECRET` from the portal; restart
- [ ] Redirect address in the portal, if asked: `https://your-address/garmin/callback`
- [ ] Notification endpoints in the portal, all pointing at the address on the Sync log page (admins only)
      (`https://your-address/garmin/webhook/<secret>`): activity summaries, activity details, activity files (FIT),
      deregistrations, user permission changes
- [ ] `python -m xcapp.cli check` reports no problems

## 3. Test with the coach's own watch

- [ ] Add a test athlete (yourself) and open the personal link
- [ ] Tick parent approval (as the adult, for testing), tap Connect Garmin, sign in, allow activities
- [ ] Page shows Connected; Sync log shows the connection and permissions
- [ ] Run a short workout with laps (for example 4 x 400 with lap presses) and sync the watch
- [ ] Within minutes: run on the athlete page, reps detected, heart-rate recovery shown, device name shown
- [ ] Plan a workout for that day and confirm the run is matched
- [ ] Disconnect from the athlete page; confirm Garmin shows the app removed; reconnect
- [ ] Remove the app from inside Garmin Connect; confirm the Sync log records the deregistration

## 4. Pilot checks (first two weeks)

- [ ] Every pilot athlete's runs arrive the same day (compare with Garmin Connect)
- [ ] No duplicate runs when a summary arrives before its file
- [ ] Token refresh works overnight (nightly job in the `scheduler` container)
- [ ] Sync log free of repeated errors

## If something goes wrong

| Symptom | Where to look |
|---|---|
| Connect fails or loops | Redirect address in the portal and `BASE_URL`; Sync log |
| Runs never arrive | Endpoint settings in the portal; webhook secret in the address; Sync log "unknown Garmin user" |
| Runs arrive without laps or heart rate | Activity file notifications not enabled; only summaries arriving |
| "Refusing to download from a host that is not Garmin's" | Add Garmin's file host to `GARMIN_FILE_HOSTS` |
| Athlete shows "Needs reconnect" | Refresh token expired or revoked; athlete reconnects from their link |
